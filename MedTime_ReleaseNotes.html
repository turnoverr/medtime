Architecture & Foundation
R-01
Convert to PWA
v2.0
In Scope
Plain English
Turns MedTime into a properly installed app on your phone — with a real icon, splash screen, and reliable background behaviour. Everything else in v2.0 depends on this being in place first.
Technical
Web App Manifest (manifest.json) + Service Worker (sw.js). Single HTML file refactored into index.html, style.css, app.js.
Why
Required for reliable iPhone notifications and proper Home Screen installation.
⚠ Must be completed before R-02 and R-03.
R-03
Offline Mode
v2.0
In Scope
Plain English
MedTime should work with no internet connection. All data stays accessible and any actions taken offline sync automatically when you reconnect.
Technical
Service Worker Cache API for app assets. Background Sync API for queued offline actions.
Why
Medication tracking should never fail due to a poor signal.
R-05
Lightweight Backend Service
v2.0
In Scope
Plain English
A small piece of software running in the cloud that sends push notifications at the right time and securely connects your two devices. You never interact with it — it runs silently in the background.
Technical
Firebase Cloud Functions (Node.js). Handles VAPID push delivery, cron scheduling, and the household pairing endpoint (R-06).
Why
Server-side scheduling is required for reliable push. The phone cannot reliably schedule its own wakeup.
Cloud Sync
R-04
Cloud Sync via Firebase
v2.0
In Scope
Plain English
Both devices share the same live data. The moment one of you marks medication as taken, the other phone updates automatically — no refreshing needed.
Technical
Firebase Firestore replaces localStorage as primary data store. Both devices subscribe to onSnapshot() real-time listeners. localStorage remains as offline cache (R-03).
Why
Without this, each phone is completely independent — neither knows what the other is doing.
Free Firebase Spark plan is more than sufficient for this use case.
R-06
Household Pairing (6-digit code)
v2.0
In Scope
Plain English
One-time setup: one person generates a short code, the other types it in — phones linked. No accounts, no email, no passwords.
Technical
UUID household ID generated on first launch. 6-char alphanumeric code maps to ID server-side (expires 10 min). Second device receives ID and reads/writes to the same Firestore document.
Why
Enables shared real-time data without requiring user accounts.
Notifications
R-02
Reliable Background Push Notifications
v2.0
In Scope
Plain English
Current notifications fail if Safari is closed. This delivers a true push — wakes your phone at the scheduled time like a text message arriving.
Technical
Web Push API with VAPID keys. Backend (R-05) dispatches pushes at scheduled times via cron. Service Worker handles the push event and calls showNotification().
Why
The most important reliability improvement for daily use.
⚠ Requires iOS 16.4+ and PWA installation (R-01).
R-07
Snooze Notification
v2.0
Planned
Plain English
A "Snooze 15 min" button on the reminder notification delays it without dismissing — useful if you're in the middle of something.
Why
Reduces the chance of dismissing and then forgetting entirely.
Depends on R-02. Will degrade gracefully where not supported.

Future Vision
R-13
Advanced Mode — Scheduled Dosing
v3.0+
Future
Plain English
A toggle in the burger menu transforms MedTime from Simple Mode (one daily reminder) into a full scheduled dosing app — morning, lunch, dinner, and bedtime slots, each with their own medications, doses, and professional instructions. Each slot tracks independently with its own history and push notification. Advanced Mode can be switched on or off at any time without losing data. A clinical-grade export makes hospital admissions and carer handovers easy — structured like a medication administration chart that nursing staff can read at a glance.
Technical
State model extended to named dose slots. Each slot: {slotName, time, medications:[{name, dose, form, instructions}], taken, takenAt, events[]}. Per-slot push notifications via backend (R-05). Export: tabular PDF/CSV with slot names as columns and dates as rows — designed to align with hospital NMR (National Medication Record) format. Builds on R-10, R-11, R-05.
Why
Most people managing health conditions take multiple medications at different times. A single reminder doesn't serve them. The export is specifically designed for hospital admissions where nursing staff need an accurate medication list immediately on arrival.
Major feature — warrants its own version milestone (v3.0). UX must remain easy to read even when the underlying schedule is complex.
R-14
eScript QR Scan-to-Import
v3.0+
Future
Plain English
Scan your Australian eScript QR code to automatically fill in medication name, form, dose, and instructions — no manual typing. Your doctor sends you the eScript by SMS or email; instead of just showing it to the pharmacist, you'd also scan it into MedTime.
How eScripts actually work
Important: the QR code in an Australian eScript is NOT a self-contained data record. It's a secure token (a pointer) to your actual prescription stored on the National Prescription Delivery Service (NPDS), operated by Fred IT Group. Only conformant software registered with the Australian Digital Health Agency (ADHA) can use the token to retrieve prescription data. The full record (medication name, dose, instructions, repeats, PBS code) is in FHIR MedicationRequest format on the NPDS — but it's locked behind formal registration.
Two pathways
Near-term (no registration): The human-readable text shown when you open your eScript link displays the medication name, quantity, and date. MedTime could offer assisted import from that screen — faster than typing, no compliance needed.

Long-term (full integration): Register as a Mobile Intermediary under the ADHA conformance scheme, unlocking access to the full FHIR prescription record including dose form, strength, detailed dosing instructions, and repeats. Apps like Scripty, MedAdvisor, and OpenPharmacy have already done this.
Near-term path (Pathway B) is the realistic first step. Full ADHA conformance (Pathway A) is a longer-term goal with legal and security obligations. Relevant standard: NPDS Conformance Profile v3.0.1.
